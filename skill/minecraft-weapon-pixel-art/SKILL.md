# Minecraft 武器像素画：固定 32×32 画板

这个 skill 只做一件事：**在固定的 32×32 画板上，用原生像素画 Minecraft 武器图标。**

不要先生成大图再缩小，不要用平滑滤镜，不要把 16×16 的图标放大 2 倍冒充 32×32。
武器识别靠剪影和负空间，不靠堆花纹。

## 为什么固定 32×32

- 32×32 刚好放得下 1px 描边、1px 刃口、1px 高光、护手、金箍、斧须、后刺。
- 16×16 只适合 vanilla 小图标；战斧、军刀、大剑在 16×16 会挤成叶子或三角形。
- 固定画板让不同武器风格一致，也让“细节密度”可比较。
- 画板固定后，所有问题都变成“这个像素该不该存在”，而不是“要不要换尺寸”。

## 画板契约

- 32×32 RGBA PNG。
- 透明背景，alpha 只有 0 或 255。
- 1px 透明边距：所有可见像素的 bbox 必须在 `x=1..30, y=1..30`。
- 右下角 2×2 必须透明，给物品栏堆叠数字留位置。
- 一个连通物体；不允许漂浮的像素、断开的护手、悬空的高光。
- 每种材质 3–5 个明暗；整张图通常 9–15 色，最多 32 色。
- 无抗锯齿、无渐变、无文字、无背景、无发光、无粒子。
- 上左打光；刃口的亮边是“磨锋”的材质提示，不是第二光源。

## 先剪影，后材质

1. 先用占位色 `X` 画 alpha 剪影，只画形状，不画材质。
2. 渲染后看 `silhouette.png`：在 1x 大小下能不能认出是什么武器？
3. 认不出就改形状，不要靠颜色救。
4. 剪影通过后，再把 `X` 换成材质字符；外轮廓保持连续。
5. 检查负空间：斧须和柄之间、护手和刃之间、刀背和握柄之间，必须有“透气”的缝隙。负空间是武器识别的一部分。

## 比例预算

32×32 不是“把 16×16 放大 2 倍”。同样一把剑，在 32×32 上要有 32×32 的体量；如果可见像素只有 90 个左右，通常说明你画的还是 16×16 的细剑。

| 武器 | 目标可见像素 | 刃/头宽 | 护手/金箍跨度 | 握柄长 | 柄尾 |
|---|---|---|---|---|---|
| 长剑 longsword | 130–180 | 刃根横向 6–7 格（垂直刃轴约 4–5px） | 10–12 格 | 7–9 格 | 4×4 |
| 巨剑 greatsword | 180–240 | 刃根横向 9–12 格 | 13–15 格 | 8–10 格 | 4×4 |
| 军刀 saber | 120–170 | 刃根横向 5–6 格 | 8–10 格 | 6–8 格 | 4×4 |
| 短刀 knife | 90–120 | 刃根横向 4–5 格 | 6–8 格 | 4–6 格 | 3×3 |
| 长枪 spear | 130–180 | 枪头 5–7 格，枪杆 2–3px | 枪箍 3–5 格 | 杆长 24–28 格 | 3×3 |
| 战斧 war axe | 140–200 | 头宽 12–16 格 | 金箍 4–5 格 | 3–4 格宽 | 3×3 |
| 镐 pickaxe | 130–180 | 头宽 12–16 格 | — | 3–4 格宽 | — |
| 弓 bow | 120–170 | 弓臂 2–3 格 | — | 握把 4–5 格 | — |

画完剪影先数一下可见像素：低于目标就先加宽刃根、护手、握柄，不要急着上色。长剑的握柄只有 4–5px 时，它会读成短剑而不是长剑。

## 武器原型与识别锚点

| 武器 | 必须有的锚点 | 关键负空间 | 常见错误 |
|---|---|---|---|
| 长剑 longsword | 直刃、护手、握柄、剑首 | 护手把刃和柄分开 | 刃太宽变成砍刀；护手 floating |
| 军刀 saber | 弯刃、单锋、护手/护指、握柄 | 弯刃内侧的月牙形空隙 | 刃是直的；弯度只在颜色里，不在剪影里 |
| 战斧 war axe | 斧头、斧须、后刺、金箍、斜柄 | 斧须和柄之间 | 实心三角；后刺像天线 |
| 镐 pickaxe | 横头、双尖、斜柄 | 头与柄的连接处 | 画成锤子；头太窄 |
| 弓 bow | 上下弓臂、握把、弓弦 | 弓臂和弦之间 | 弦断；弓臂对称得像括号 |

### 长剑 recipe

- 轴线：左下握柄 → 右上剑尖，约 45°。
- 刃：刃根横向 6–7 格（垂直刃轴约 4–5px），向剑尖以 1px 台阶收窄到 1–2px。
- 刃面：外圈深色描边，内部一条 1px fuller（血槽），一侧亮、一侧暗。
- 护手：与刃轴垂直，10–12px 长、2px 厚，金色；两端可以微微下弯，但不能断开。
- 握柄：7–9px 长、3–4px 宽，皮革/深色；长剑是双手/手半剑，4–5px 会读成短剑。用连续的 1px 缠绕带，不要棋盘格。
- 剑首：4×4 金色，压住左下角视觉重心。
- 参考锚点（可调整）：护手中心约 `(11,21)`，剑尖约 `(27,3)`，剑首约 `(3,28)`。

### 巨剑 recipe

- 从 `--template longsword` 开始，把刃的切割边加宽 2–3 格，目标 180–240 可见像素。
- 刃根横向 9–12 格；护手 13–15px；握柄 8–10px；剑首 4×4。巨剑的识别靠“宽刃 + 大护手”，不是靠更长。
- 护手可以做成贝壳形/弧形，但两端必须接在刃轴和柄上；不要 floating。
- 32×32 放不下时，宁可缩短刃长，也不要缩窄护手和刃根。
- 刃面可以加 1px 波浪/海晶纹，但每条纹路都要连续，不能变成噪点。

### 水晶军刀 recipe

- 轴线：左下握柄 → 右上刀尖，但**必须弯**。刀尖向上/向外勾，弯度要出现在 alpha 剪影里。
- 刃：刃根横向 5–6 格，单锋；凸面是刃口，凹面是刀背。
- 刃口：沿凸面一条 1px 亮边（crystal light/highlight），刀背用 deep/shadow。
- 晶面：2–3 条 1px facet 线，不要每像素渐变；高光只放在刀尖和刃口转折处。
- 护手：金色，8–10px；推荐加 1px 护指弓，从护手外端连到剑首，两端都必须接上。空间不够时用 8–10px 护手代替。
- 握柄：6–8px 长、3–4px 宽，略弯，深色皮革；剑首 4×4 金色。
- 参考锚点（可调整）：护手中心约 `(10,21)`，弯刃控制点约 `(12,20) → (19,13) → (25,8)`，刀尖约 `(29,3)`。

### 短刀 recipe

- 可用 `--template knife`；刃比长剑短 8–12 行，刃根横向 4–5 格，向刀尖收窄到 1px。
- 护手 6–8px、2px 厚；握柄 4–6px、3px 宽；柄尾 3×3。
- 折叠刀：刃身分成 3–4 段，每段 2–3px 厚，段与段之间留 1px 亮缝；所有段必须连在同一刀脊上。
- 半透明蜂蜡/蜜蜡：不要用 partial alpha（画板要求 0/255）；用“浅琥珀核心 + 亮刃口 + 深琥珀外描边”模拟透光。
- 刀柄六边形蜂巢纹：用连续的 1px 折线画 2–3 个六边形，不要逐像素棋盘格。

### 长枪 recipe

- 可用 `--template spear`；枪杆 2–3px 宽、24–28 格长，枪头 5–7 格宽、8–12 行高。
- 枪头必须明显宽于枪杆，并在连接处加 3–5 格枪箍；否则会读成一根棍子。
- 两侧导轨用 1px 线，沿枪杆平行走，两端都要接在枪箍/枪尾上，不能悬空。
- 枪尾坠饰：1px 链子 + 3–4px 碎片；链子要接到枪尾。
- 枪头/枪杆用不同材质时，外描边用各自的 deep 色，枪箍用 metal ramp。

### 战斧 recipe

- 斧头在右上，斧须向下勾，后刺向左上，金箍在刃和柄的机械连接处。
- 斧须和柄之间留 1–2px 透明缝；没有这条缝，头会变成实心三角/叶子。
- 后刺基部至少 2px 宽，不要画成 1px 天线。
- 柄是 3px 斜带：上缘 light、中间 base、下缘 shadow；金 pommel 压住左下角。
- 参考示例：`examples/emerald_war_axe.json`。**只用来校准细节密度，不要复制它的剪影。**

## 材质系统

`board.py init` 会生成这套字符表：

| 字符 | 角色 |
|---|---|
| `D` | 主材质 deep / 外描边 |
| `S` | 主材质 shadow |
| `B` | 主材质 base |
| `L` | 主材质 light |
| `H` | 主材质 highlight |
| `G` | 金色 deep / 描边 |
| `g` | 金色 shadow |
| `y` | 金色 base |
| `Y` | 金色 light |
| `w` | 握柄 deep / 描边 |
| `u` | 握柄 shadow |
| `o` | 握柄 base |
| `k` | 握柄 light |
| `X` | 品红占位色；最终图不能保留 |

可用主题：`steel`、`deepslate`、`emerald`、`echo`、`sculk`、`copper`、`redstone`、`honey`、`amber`、`crystal`、`ender`、`amethyst`、`magnetite`、`obsidian`、`tidal`、`prismarine`、`shell`、`seaweed`、`blaze`。
握柄可选任意带 `deep/shadow/base/light` 的主题（`wood`、`leather`、`seaweed`、`sculk` 等）。

### 多材质

```bash
python scripts/board.py init --out spec.json --template longsword \
  --primary deepslate --secondary echo --grip sculk --name echo_blade
```

`--secondary` 会额外生成一套 `d/s/b/l/h`。标准分工：

- `D/S/B/L/H`：主材质（刃/头/杆）。
- `d/s/b/l/h`：副材质（镶嵌、脉络、线圈、纹样）。
- `G/g/y/Y`：金属/配件 ramp。不一定是金；铜护手、避雷针、枪箍、贝甲都可以用它，按设计改 hex。
- `w/u/o/k`：握柄（木、皮革、海带、布条）。
- `X`：剪影占位色。

第三种点缀可以手动加键（如 `m/n/p/q`），每种 3–5 个明暗；总色数 ≤32。

规则：

- **Material-aware outline**：用每种材质自己的 deep 色做描边，不要全图纯黑。
- **上左光**：上缘/左缘 light，下缘/右缘 shadow。
- **刃口亮边**：沿切割边的 1px light/highlight，是“锋”的提示；不要把它扩展到整个右半身。
- **金色只放在机械关节**：护手、金箍、剑首、斧座。不要随机撒金点。
- **缠绕带**：沿柄轴连续的 1px 斜带；不要 `wowow` 棋盘格。
- **颜色预算**：3px 宽的刃用 3 个主色 + 描边即可，不必把 5 个色全用上。

## 像素预算

- 描边 1px，刃口 1px，高光 1px；不要 2px 黑框。
- 不要 2×2 的 macroblock（那是 16×16 放大 2 倍的味道）。
- 细节必须长在 1px 网格上：剑尖收窄、斧须勾、护手端部、facet 线。
- 不要填满画板；留 1px 边距和右下角 2×2。
- 没有功能的装饰（符文、宝石、光环、粒子）一律删掉。

## 工作流（低步数版）

1. 选原型。标准武器优先用比例模板，不要从零画剪影：

```bash
python scripts/board.py init --out spec.json --template longsword \
  --primary deepslate --secondary echo --grip sculk --name echo_blade
```

模板只是比例骨架（整把都是 `X`），必须改轮廓、尖端、护手/刀镡；不能直接交付。
可用模板：`longsword`、`crystal_saber`、`war_axe`、`knife`、`spear`。巨剑用 `longsword` 加宽；没有合适模板时用 `--template none` 生成空白板。

2. 在 `spec.json` 的 `rows` 里把 `X` 换成材质字符。可以写一个小 Python 脚本批量填行，脚本留在输出目录方便复现。
3. 快速迭代：每轮只出 candidate、review 和校验摘要：

```bash
python scripts/board.py render --spec spec.json --out candidate.png --preview-dir . --fast
```

**只 Read `review.png`**。它一张图包含 8x 中灰/浅色/深色、GUI 16px、silhouette 五个面板；不要逐张读 `preview_8x*.png`。
4. 先修剪影，再修材质。看 review 的 `silhouette` 和 `GUI 16px` 两个面板判断识别度；8x 面板判断描边和材质。
5. 需要具体坐标时加 `--ascii`，它直接打印 32 行字符图，比读图更快。
6. 至少两轮：剪影轮 + 材质轮；只有 validation 失败或剪影仍不读时才加第三轮。
7. 最终交付去掉 `--fast`，出全套 preview，并生成 process.md 骨架：

```bash
python scripts/board.py render --spec spec.json --out candidate.png --preview-dir . --process-template
```

8. 画多把武器时：先把所有 spec 写好，再用一条 Bash 命令批量 render，然后一次性看各自的 `review.png`；不要一把一把串行读图。
9. 修 `validation.json` 里的 error；**stdout 已经打印了 error/warning 和像素数，不需要为了摘要再读 JSON**。warning 要判断，不要盲目忽略。
10. 交付 `candidate.png`、`review.png`、`preview_8x*.png`、`silhouette.png`、`validation.json`、`spec.json`、`process.md`。

## 工具输出

- `review.png`：**首选检查图**。一张图里依次是 8x 中灰、8x 浅色、8x 深色、GUI 16px、silhouette。
- `--fast`：只写 `candidate.png`、`review.png`、`validation.json`，适合迭代。
- 不加 `--fast`：额外写 `preview_8x.png`、`preview_8x_light.png`、`preview_8x_dark.png`、`silhouette.png`，适合最终交付。
- `validation.json`：原始数据；stdout 已有摘要，除非要读数组，否则不用打开。
- `--ascii`：把 32 行字符图打印到 stdout，查坐标时比读图快。
- `--process-template`：如果 `process.md` 不存在，写一个带当前指标的骨架；设计说明由 agent 填。

## 验证器会检查什么

`board.py render` 自动写 `validation.json`：

- 尺寸必须 32×32。
- alpha 必须 0/255。
- bbox 必须在 1..30，不能贴边。
- 右下 2×2 必须透明。
- 只能有一个连通分量；漂浮像素会报 error。
- 可见颜色 ≤32；>24 会给 warning。
- 可见像素 <60 会 error（太稀疏，读不出 32×32 武器）；<110 会给 warning（很可能把 16×16 直接放大了）。
- 可见像素 >550 会给 warning。
- `X` 占位色残留会给 warning。

error 必须修；warning 要说明为什么可以接受。

## 常见失败与修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 剑头像叶子 | 头是实心三角，没有负空间 | 收窄颈部，加斧须/凹口，留出柄与头之间的缝 |
| 后刺像天线 | 1px 细线，基部没接上 | 基部加到 2px，直接接在斧座/头上 |
| 护手 floating | 护手和刃/柄之间有透明缝 | 让护手中心压住刃轴，端部与刃/柄至少共享 1px |
| 柄像棋盘格 | 逐像素交替明暗 | 沿柄轴画连续 1px 带：上 light、中 base、下 shadow |
| 描边有洞 | 只看外轮廓，没检查内凹处 | 每个暴露在透明背景上的像素都换成该材质的 deep 色 |
| 军刀像长剑 | 弯度只在颜色里 | 改 alpha 剪影：刀尖上勾，凸面刃口，凹面刀背 |
| 32×32 像 16×16 放大 | 2×2 macroblock | 用 1px 台阶重画轮廓，加 1px facet/bevel |
| 画面太满 | 想塞太多装饰 | 删掉非功能元素，留边距和负空间 |

## 交付前 checklist

- [ ] 1x 剪影能认出武器类型
- [ ] 可见像素在目标范围（长剑 130–180，军刀 120–170，战斧 140–200）
- [ ] 刃根/护手/握柄比例符合原型，不是 16×16 放大
- [ ] 关键负空间没有被填死
- [ ] 护手/金箍/斧座在机械关节上，且连接牢固
- [ ] 外描边连续，没有透明洞
- [ ] 每种材质 3–5 个明暗，总色数 ≤32
- [ ] 1px 边距，右下 2×2 透明
- [ ] 没有漂浮像素、没有残留 `X`
- [ ] `validation.json` 无 error
- [ ] `review.png` 已一次看全（明/暗/GUI/剪影），没有逐张读 preview
- [ ] 浅色/深色背景预览都能读
- [ ] `process.md` 记录了设计理由和至少两轮修改
